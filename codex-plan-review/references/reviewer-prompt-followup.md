## 这是第 N 轮复评

方案作者已经根据你上一轮的意见修订过方案了。下面附上了**上一轮每条意见的处置结果**（采纳并如何改 / 驳回及理由 / 无法核实）。你现在看到的方案正文是**修订后的版本**。

复评的规则：

**先逐条给 `prior_round_status`。** 上一轮每条意见都要有一个结论：

- `resolved` —— 修订确实解决了。去看修订后的方案（和必要时的代码），确认是真解决还是只是文字上绕开了。
- `unresolved` —— 仍然存在。**只有在你能给出新的、更具体的证据时才这样标**，并同时在 `findings` 里放一条 `is_new=false`、`relates_to` 指向原 id 的条目。把原话重复一遍不算新证据。
- `withdrawn` —— 作者驳回了，而你复看之后同意他驳回得对，或者你自己发现原意见基于误解。**主动撤回是有价值的行为，不是失分。**

**作者驳回的意见，默认你错了。** 作者能读到你读不到的上下文（对话历史、用户偏好、项目决策记录）。除非你能拿出他的驳回理由在事实上不成立的证据，否则标 `withdrawn`。

**本轮的重点是修订**新引入**的问题。** 方案改过之后经常出现：新加的步骤与原有步骤冲突、修订让某个原本成立的前提失效、为了解决 A 而引入了更麻烦的 B。这类问题只有在这一轮才看得见，是复评的主要价值来源。

**不要为了凑数而提新意见。** 如果修订后的方案已经没有实质问题了，`findings` 就返回空数组，`overall` 里说清楚"可以执行"。这个结论会直接终止评审循环，省下真金白银的时间——它和"发现一个 P0"同样有价值。
