# 结构分析与页面设计

## 第一步：结构分析

读取文档后，识别以下结构元素并记录数量与内容：

| 元素类型 | 识别特征 | → 可视化形式 |
|---|---|---|
| 里程碑/阶段 | M0~Mn、Phase N、阶段 | 带可展开任务的路线图卡片 |
| 嵌套任务树 | Mx-Sy-Tz、子任务列表 | 可折叠树（三级） |
| 硬性约束/红线 | 红线、禁止、MUST NOT、冻结条款 | 红色警告卡 + 图标 |
| 假设/实验 | H1~Hn、待验证假设 | 状态徽章卡片 |
| 架构分层 | 四层、Layer、数据层/指标层/… | 层叠堆栈图 |
| 依赖关系 | blocks/blockedBy、前置条件 | 流程图（优先手写 SVG） |
| 数据事实表 | markdown 表格、事实摘要 | 可排序交互表 |
| 实现陷阱 | 雷区、Rn、注意点 | 折叠警告列表 |
| 关键决策 | 冻结口径、已确认设计 | 决策卡片网格 |

**提取元数据**：文档标题、一句话摘要、日期、核心数字（几个里程碑、几条红线…）——这些直接进 Hero 区。

## 第二步：页面结构设计

按内容决定标签数量，**没有对应内容的标签不生成**：

| 标签 | 放什么 |
|---|---|
| 概览 (Overview) | 标题卡、关键统计数字、架构层叠图、依赖关系图（手写 SVG） |
| 路线图 (Roadmap) | M0→Mn 可展开卡片 → 展开见切片 → 展开见任务 |
| 约束与决策 (Rules) | 红线警告卡（**全部展示，不折叠**）、冻结决策列表 |
| 假设追踪 (Hypotheses) | Hn 卡片网格，含期望结论和触发条件 |
| 实现指南 (Guide) | 雷区列表、关键锚点表、技术注意事项 |
| 数据事实 (Data) | 文档中的数据表格、画像数字等 |

> 红线/冻结条款**不折叠**：它们是读者最需要一眼看到的约束，藏进 `<details>` 会失去警示作用。

## 配对文档（设计 + 结果）的专用结构

常见于"预注册（prereg）+ 判决书"、"设计方案 + 结项报告"这类配对 —— 设计在前、结果在后，两条线要能逐项对上：

| 标签 | 放什么 |
|---|---|
| 概览 | 一句话结论 + 判决流水线图 + 关键读数速览 + 核心机制（"为什么会有这个结论"） |
| 实验设计（冻结） | 三元组/参数/对照、**口径冻结**（含被覆盖的原生配置及原因）、检验口径、开放预期 |
| 逐层结果 | 每层一张卡：结论徽章 + 读数卡组 + 白话解释 + `<details>` 机制拆解 + `<details>` 原始读数 |
| 为什么重要 | 跨案例复现的证据、"这次特殊在哪"的对照卡 |
| 产物与共性 | 可复现参数（种子/数据签名）、产物路径清单、术语速查 |

### ★ 两处硬要求

1. **逐层结果卡必须同时保留"改写后的读数"和"原文摘录"** —— 改写是给理解用的，原文是给核对用的，不能互相替代；`<details>` 做第二层正合适。
2. **涉及"正/负增量、改善/恶化"的方向性表述，改写时必须回到原文逐字核对。** 统计判决里最容易被写反的正是方向（如"收窄 41pp 中信息部分 −1.9pp"意味着时点选择**有害**，不是"改善不足"）——写反比不写更糟。详见 `rewriting.md`。

## 一句话结论怎么写

概览页的结论句是全页最重要的 30 个字。写法定式：

> **（判决/结论本身）——（关键机制使然）。** 一句话讲清"发生了什么"，紧跟一句讲清"为什么会这样"。

再配 2~4 张对照卡（每张：一个结论 + 一个关键读数 + 一句人话），让读者不展开任何折叠就能抓住全貌。

## 关键读数速览的写法

用 3~4 列的读数卡网格（每格：指标名 + 大号数字 + 一行备注）。注意：

- 数字用 `tnum`（等宽数字）避免跳动；
- 颜色跟语义走，不要全部一个色；
- **每格备注不超过一行**——窄列里两行备注会撑破卡片，这是断言查不出来的排版问题（见 `build-and-verify.md` 的裁剪目检）。
