# 用普通话改写（本技能最高优先级）

原文是写给领域专家的，充斥着行话缩写。**任务是把内容翻译给初次接触这个方向的人看。**

每一条内容都要问自己：*"一个聪明但不了解这个项目的人，读完能明白这在说什么吗？"*
如果不能，就改写。不要因为"忠于原文"而保留读者看不懂的内容。

## 三种处理方式（按优先级）

**1. 直接替换**：能用大白话说清楚的，直接改写，删掉原始术语。

> ❌ `vol正向预测收益、守卫/择时/regime降仓/vol-targeting四者同因失败`
> ✅ `过去试过四种减少亏损的方法：自动止损、择时操作、仓位控制、波动率调仓——测试下来全部在同一个地方失败：市场最低迷时把股票卖掉了`

**2. 注释保留**：专业术语不可避免时，在括号内补一句大白话。

> ❌ `ETL建成后M1附带行动项验证`
> ✅ `数据管道（ETL）搭好后，顺手验证这个猜想`

**3. 术语悬浮提示**：必须保留的专业词汇，用 tooltip 包裹。

```html
<span class="tooltip-term" title="从多个原始 CSV 文件读取、清洗、统一格式后写入 parquet">ETL</span>
```

配套 CSS（简写类名 `.tt` 等价，整页 CSS 见 `html-authoring.md` 的骨架）：

```css
.tt, .tooltip-term {
  border-bottom: 1px dashed #94a3b8;
  cursor: help;
  color: #475569;
}
```

## 常见行话翻译参考

| 原文术语 | 改写建议 |
|---|---|
| ETL / parquet | 数据处理管道 / 列式存储文件 |
| regime | 市场状态（牛市/熊市/震荡等） |
| vol / volatility | 价格波动幅度 |
| lag=N 交易日 | 数据延迟 N 个交易日才能用 |
| generation | 一次完整的数据构建结果 |
| fingerprint / 指纹 | 文件哈希校验值（用于检测数据是否被篡改） |
| sentinel / 哨兵 | 自动检测异常的守卫程序 |
| GC 保护 | 防止被自动清理 |
| 前视 / look-ahead | 回测时不小心用到了未来的数据（作弊） |
| 幸存者偏差 | 已退市的失败股票不在数据里，导致结论过于乐观 |
| prereg / 预注册 | 先写下判断标准，再去看数据，防止事后挑指标 |
| 口径 | 同一个指标的具体算法约定（换口径 = 换算法，数字会变） |
| null 分布 | 用随机/平移生成的"假信号"跑出来的对照分布 |
| bootstrap | 反复重采样来估计"结论有多不确定" |
| SEM | 逐年数据的标准差，直接决定置信区间宽窄 |
| MDD / 最大回撤 | 从最高点跌下来的最深幅度 |
| 回撤面积 | 净值低于前期高点的累计面积，同时刻画深度与时长 |
| ADAR | 年化收益 ÷ 年化回撤面积比——把"跌多深"和"跌多久"一起算的收益风险比 |
| 暴露率 / 仓位 | 有多少比例的资金真的在场内 |
| 换手 | 一年里仓位来回变动的倍数，直接换算成手续费 |

> 这张表按项目持续增补。**遇到新行话，先想"能不能直接换成大白话"，换不掉才进表。**

## 两层内容模式

每张卡片/条目用"摘要 + 可选技术详情"的两层结构：先说人话，再给原文。

```html
<div class="border rounded-xl p-4">
  <p class="font-semibold">一句话说清楚这是什么</p>
  <p class="text-sm text-gray-600 mt-1">用普通话解释为什么重要、会发生什么</p>
  <details class="mt-3">
    <summary class="text-xs text-gray-400 cursor-pointer hover:text-gray-600">原始技术细节 ▾</summary>
    <p class="text-xs text-gray-500 mt-1"><!-- 原文摘录或更详细的技术说明 --></p>
  </details>
</div>
```

**两层不能互相替代**：改写层是给人理解用的，原文层是给人核对用的。删掉任何一层都会让这份产物失去价值——只留改写层则不可核对，只留原文层则等于没做可视化。

## ★ 方向性表述：必须回原文逐字核对

统计判决类文档最容易写反的就是**方向**。改写"正/负增量、改善/恶化、超过/低于"这类表述时，必须回到原文逐字比对，不要凭语感推断。

典型陷阱：

> 原文「收窄 41pp 中信息部分 −1.9pp」
> ❌ 误写成「改善不足」　✅ 正确含义是「时点选择**有害**」（信息部分是负贡献）

**写反比不写更糟**——读者会据此做出反向决策。核对成本很低，误判成本很高。

## ★ 源文档内部不一致时：标注，不要擅改

同一数字在原文两处不一致（很常见：摘要写一个值、明细表写另一个值），**不要自己挑一个采信**。正确处理：

1. 页面上按各自所在章节/文件原样呈现；
2. 用一行小字显式标注差异与量级（"两处口径并存，差 0.4pp 级，不影响判决方向"）；
3. 需要引用单一数字时，明确提示用户先确认口径。

同理，读数应以**冻结产物**（JSON/CSV）为准核对一遍：若摘要与产物不一致，两者都要如实登记。
