# 手写内联 SVG（首选路线）

仪表板里 90% 的图 —— 流程链、层级堆栈、时间轴、对比柱、分解瀑布、散点、泳道 —— **手写内联 SVG 比 mermaid 更快也更稳**：

- **完全可控**：坐标自己定，不会出现"某节点文字被框裁掉""整图被缩到 8px"这类布局意外；
- **零运行时依赖**：不引 mermaid、不预渲染、不担心外部工具抢渲染 —— `mermaid-pitfalls.md` 的六个坑一次性全部绕开；
- **配色可严格对齐**页面语义色系统（见 `html-authoring.md`）。

## 上手要点（都是踩过的）

1. 根 `<svg>` 同时给 `width` / `height`（自然尺寸，通常 900~1000 宽）与**等值** `viewBox`，外面套一个滚动容器，CSS 写 `max-width:none;height:auto` —— 宽图按**自然尺寸横向滚动，文字保持原始大小**：

   ```html
   <div class="svg-wrap">
     <svg width="980" height="170" viewBox="0 0 980 170" role="img" aria-label="一句话描述这张图">
   ```

   > 容器类名只要**不含 `mermaid` 字面量**即可（避免被外部工具抓走重渲染）。建议统一用 `.svg-wrap`（历史产物也有用 `.mmd-svg` 的）；**一个文件里只用一种**。

2. `font-family` 显式写在根 `<svg>` 上（`system-ui,-apple-system,'Segoe UI','Microsoft YaHei',sans-serif`），否则不同环境回退字体宽度不同、排版会变。

3. 每个图配 `role="img"` + `aria-label`（描述图在讲什么，不是罗列元素）。

4. ★ **文本越界自查**：`text` 同时用 `text-anchor="middle"` 和 `dy="-4"` 时，`getBBox()` 的 top 会变成负数 —— 根 `<svg>` 默认 `overflow:hidden`，**会被无声裁掉**（实测轴标题被裁 2px，肉眼几乎看不出）。贴边文字留 4~6px 余量，并用断言脚本查（见 `build-and-verify.md`）。

5. ★ **纵轴旋转标题是越界"误报"的重灾区**：`<text transform="rotate(-90 x y)">` 的 `getBBox()` 返回的是**旋转前**的局部框（半宽 = 文字宽度/2），所以只要 `x` 小于半宽就会被断言报越界，**哪怕视觉上完全在画布内**（实测被误报过两轮）。两种修法，**优先缩标题**：
   - **缩标题**（首选）：纵轴标题压到 **≤4 个汉字**（「空仓成本（pp/年）」→「空仓成本」、「年化收益（%）」→「年化收益」），单位/说明挪进图标题或图下注释；
   - **挪 `x`**：取到 ≥ 未旋转半宽 + 4（短标题「年化 pp」约 40px 宽，`x≈24~26` 即可）。

   > 宽度估算：**汉字 ≈ `font-size × 1.0`，半角 ≈ `× 0.55`**。宁可按估宽先定 `x`，再跑断言。

6. SVG 文本**不会自动换行**：一个 `<text>` 一行，多行就给多个 `<text>` 各配一个 `y`。

7. ★ **越界断言抓不到"文字压文字"，必须另做重叠检测**：越界断言是逐个元素比 `viewBox`，两块文字叠在一起时**两边都在框内**，于是整页 0 错误通过、实际渲染里长句却压住了右侧徽章、两条脚注叠成一团，**只能靠 2× 裁剪目检才发现**（实测漏检过两版）。修法：对同一 SVG 内所有 `text` 两两求交，交集面积超过**较小框的 25%** 就报（见 `build-and-verify.md` 的 ③b 断言）。布局时预留两件事：
   - 右侧栏（徽章 / 图例 / 状态胶囊）的起点 `x` 要 ≥ 左侧最长句子的右边界 + 8px —— **长句宽度务必按第 5 条的估算法先算一遍**，凭感觉给起点必翻车；
   - 整段长注释宁可拆成两个 `<text>` 各配一个 `y`，不要指望它能塞进一行。

8. ★ **图内出现 `NaN` 字面量会误触 NaN 断言**：若图注引用了原文术语（如「NaN 保持」），宽松写法 `/translate\(undefined|NaN/` 会误报。断言应写成 `/translate\(undefined|translate\(NaN|,\s*NaN\)/`。

9. **画一致性**：同类元素（节点框、柱子、标记）复用同一组尺寸常量，视觉才整齐。数值映射先定"零轴 y + 每单位像素"，再算每根柱的 `y`/`height`，不要逐根目测。

## 常用图的坐标套路

| 图型 | 套路 |
|---|---|
| 流程链 | 上下堆叠的 `<rect>` + 竖直箭头（`<line>` + `<polygon>` 三角头）；每个框左侧留 22px 内边距，右侧若有徽章则框内分区：左文右章 |
| 瀑布分解 | 零轴定死；正柱向上、负柱向下，**相邻柱用虚线连接同一水平线**；末柱回到零轴起算 |
| 分组柱 | 组中心 = `起始 x + 组宽/2 + i×组宽`；两组柱各自 `中心 ∓ 18`，柱宽 32；**数值标签逐个估宽**（见第 7 条） |
| 散点/前沿 | 双轴分别定比例尺，先画网格线再放点；参考线用虚线；关键点用大半径 + 文字标注 |
| 四象限/矩阵 | 中央交叉虚线 + 四块 `<rect>`，每块内左对齐 3~5 行短句 |

## 图内的三种"两层"写法

图本身也要承担"改写 + 原文"两层职责：

1. **图标题**用改写后的说法（"钱是怎么被空仓吃掉的"），不要用原文术语；
2. **轴/单位**放图内，但纵轴标题压到 ≤4 字（见第 5 条）；
3. **图下注释**一句讲清"这张图说明什么"，并在注释里给出**数据来源**（如"数据源：`XXX.json` 的 D3 对照表"），方便核对。

## 什么时候才真的需要 SVG

如果内容是"纯文字对照"（口径冻结、术语表、产物清单），用 Tailwind 卡片/表格就够了，**不要为了好看强行画图**。图只画三类东西：

- **结构**（流程、分层、依赖、象限）——文字描述不清的；
- **数量对比**（柱、瀑布、散点）——一眼看出量级的；
- **时间/顺序**（逐年、阶段推进）——看趋势和拐点的。
