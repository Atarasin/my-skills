# 订单服务需求说明（上游）

版本：v1.2　　状态：已评审通过

## 背景

现有下单流程耦合在单体商城应用中，无法独立发布。本次将订单能力拆分为独立服务。

## 功能需求

- FR-1 用户可创建订单，订单需记录商品、数量、金额、收货信息。
- FR-2 用户可查询自己的订单列表与订单详情。
- FR-3 用户可在未支付前取消订单，取消后释放占用的库存。
- FR-4 支付完成后订单状态需在 5 秒内更新，供商城前端轮询。
- FR-5 订单数据需保留 3 年以满足财务审计要求。

## 非功能需求

- NFR-1 日订单量峰值 20 万，创建接口 P99 延迟不超过 300ms。
- NFR-2 订单服务不可用时，商城首页与商品详情页不受影响。
- NFR-3 订单金额相关计算不得出现精度误差。

## 约束

- 一期不引入新的中间件，复用现有 MySQL 与 Redis。
- 需与现有用户体系对接，不自建账号。
- 一期上线时间为 2026 年 9 月底。

## 非目标

- 不包含退款与售后流程，二期再议。
